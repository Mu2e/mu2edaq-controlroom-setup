Application Launcher Contract

Application packages integrate with the control-room desktops through config/apps.yaml, standardized start/stop scripts, and the installed crs-app dispatcher.

config/apps.yaml

Each app entry defines the app id, script names, expected checkout path, port assignments, desktop sessions, and icon behavior.

FieldMeaning
idShort identifier used by crs-app start <id>.
titleHuman-readable launcher label.
repoRepository under mu2edaq-main.
start, stopStandardized script names.
install_pathExpected app checkout path on DAQ hosts.
portsNamed port assignments exported by crs-app.
sessionsVNC sessions that receive desktop launchers for this app.
desktopIcon name and whether to run in a terminal.

crs-app

Desktop launchers call:

~/controlroom/bin/crs-app start <app-id>
~/controlroom/bin/crs-app stop <app-id>

crs-app reads ~/controlroom/etc/apps.yaml, exports configured ports, finds the start or stop script in ~/controlroom/bin or the app install_path, then executes it.

Port Environment

Each named port becomes an environment variable:

ports: {http: 8080, zmq: 5555}

CRS_PORT_HTTP=8080
CRS_PORT_ZMQ=5555

Application scripts should read these variables and should keep the standard precedence: command line, then environment, then config, then built-in defaults.

Standard Script Names

Use names matching the entries in apps.yaml, for example:

start-mu2edaq-dashboard.sh
stop-mu2edaq-dashboard.sh

The templates/ directory in this repository contains adoption templates for application packages, including man page templates.

Active Session Names

The current active sessions are dcs-main, shift-main, and trig-main. Apps assigned only to older names such as daq-main, daq-aux, daq-dl2, or shift-aux remain in the inventory but will not receive desktop launchers unless those sessions are present in config/controlroom.yaml.

Inspect Apps On A Host

~/controlroom/bin/crs-app list

Run this on a configured DAQ account to see the installed app inventory and port assignments.
