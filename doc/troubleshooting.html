Troubleshooting

No Kerberos Ticket

klist -s || kinit

Both remote lifecycle commands and tunnel opens perform a Kerberos preflight. Renew credentials before retrying.

Tunnel Reports Closed

venv/bin/crs-tunnel status
venv/bin/crs-tunnel open --session shift-main

The tunnel manager checks SSH control sockets under ~/.crs. If ssh -O check fails, it removes stale sockets so the next open can recreate the tunnel.

VNC Session Is Not Visible

venv/bin/crs-remote status --session shift-main
venv/bin/crs-remote start --session shift-main

Remote status reports both VNC display state and discovery responder state. Start the session if the display is stopped.

Viewer Does Not Launch

venv/bin/crs-tunnel connect --session shift-main --viewer /path/to/vncviewer

On macOS, the default viewer path uses open vnc://localhost:PORT. On other systems, install TigerVNC or pass a viewer explicitly.

Desktop Icons Are Missing

venv/bin/crs-remote provision --session shift-main

If icons are still missing for an app, confirm the app's sessions entry in config/apps.yaml includes an active session from config/controlroom.yaml. Also confirm its start/stop scripts exist under the configured install_path.

Discovery Scan Fails In The GUI

  • Confirm the selected remote target is reachable with Kerberos SSH.
  • Confirm mu2edaq-discover --json is available on the remote target, either in ~/controlroom/bin or on PATH.
  • Use gateway mode for production scans. Local multicast is only useful on a network segment where multicast discovery traffic is visible.

Run Tests

venv/bin/pytest

The tests cover configuration validation, tunnel command construction, viewer launch behavior, remote install payloads, and desktop launcher generation.
